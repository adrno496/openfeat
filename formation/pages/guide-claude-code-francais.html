Guide Claude Code en français — installation, configuration et premier flow

Mis à jour mai 2026 · Lecture 12 min

Claude Code est l'assistant de développement officiel d'Anthropic. Il s'utilise dans le terminal (CLI), dans VSCode (extension), ou en navigateur (claude.ai/code). Ce guide en français couvre l'installation pas à pas, la configuration projet, et le premier workflow utile pour un développeur francophone.

1. Installation de Claude Code (CLI)

Pré-requis : Node.js 18 ou plus, Git installé, un compte Anthropic actif (Pro ou Max recommandé pour usage intensif).

npm install -g @anthropic-ai/claude-code
claude --version

Premier lancement dans un projet :

cd ~/projects/mon-projet
claude

Au premier appel, Claude Code ouvre une page d'authentification OAuth dans ton navigateur. Tes credentials sont stockées dans ~/.claude/.

2. Installation de l'extension VSCode

Marketplace VSCode → recherche "Claude Code" (officiel Anthropic) → Install. Le raccourci par défaut pour invoquer l'assistant est Cmd+Esc (macOS) ou Ctrl+Esc (Linux/Windows). L'extension reprend automatiquement les credentials de la CLI.

3. Configurer ton premier CLAUDE.md projet

CLAUDE.md est un fichier markdown placé à la racine de ton projet. Claude Code le lit automatiquement à chaque session pour comprendre les conventions et contraintes du projet. Tiens-toi à 80 lignes maximum — plus c'est court, plus c'est lu attentivement.

Exemple type pour un projet Vanilla JS + Supabase :

# CLAUDE.md

## Stack
- Frontend : Vanilla JS (ES Modules natifs, pas de bundler)
- Backend : Supabase (Postgres + Auth + Edge Functions)

## Conventions code
- Indentation 2 espaces, quotes simples, sans point-virgule
- Pas de framework JS ajouté sans validation

## Trucs à ne pas faire
- Pas de select('*') Supabase, toujours colonnes explicites
- is_premium muté uniquement via RPC server-side
- Pas de innerHTML avec input utilisateur sans escapeHtml

## Commandes utiles
- npm run dev
- npx supabase migration new <nom>

4. Configurer les permissions (settings.json)

Place ton fichier de permissions dans .claude/settings.json (projet, commité en équipe) ou ~/.claude/settings.json (global, perso).

{
  "model": "claude-opus-4-7",
  "permissions": {
    "allow": [
      "Bash(git status)",
      "Bash(git diff)",
      "Bash(npm test)",
      "Read", "Edit", "Write"
    ],
    "deny": [
      "Bash(git push --force*)",
      "Bash(git reset --hard*)",
      "Bash(rm -rf /*)"
    ]
  }
}

Les commandes du allow sont auto-acceptées sans demande de confirmation. Le deny bloque même si tu autorises par erreur — c'est ta filet de sécurité contre les opérations destructives.

5. Premier flow : décrire un projet

Lance claude dans un projet et demande :

"Lis README.md et donne-moi un résumé de l'architecture du projet en 5 points."

Claude Code lit ton README, explore les fichiers nécessaires si besoin, et te répond. Tu n'as pas à lui dire où chercher — il sait. C'est le test parfait pour valider ton install.

6. Le squelette de prompt qui marche 9 fois sur 10

Un bon prompt n'est pas long, il est structuré en 4 sections :

Contexte: tel fichier fait X. On veut Y.
Objectif: ajouter / modifier / extraire Z.
Contraintes:
- ne pas toucher à A
- pas de nouvelle dépendance
Format de sortie: diff sur le seul fichier concerné.

4 sections, chacune en 1 à 3 phrases. Total : 4 à 12 lignes. Tu obtiens un résultat exploitable dès la première ou deuxième tentative.

7. Le protocole de debug à 5 points

90 % des échecs Claude Code sur un bug viennent du même problème : info manquante. Donne ces 5 éléments dès le premier prompt :

  1. Stack trace complète (jamais tronquée)
  2. Repro steps précis
  3. Comportement attendu
  4. Comportement observé
  5. Ton hypothèse (même fausse)

Avec ces 5 éléments, Claude Code va droit au but. Sans, il devine et il échoue plusieurs fois.

8. Gérer le contexte (/clear vs /compact vs sessions courtes)

Le "contexte" est la mémoire de session de Claude Code. Plus elle est longue, plus chaque tour est cher et moins la qualité est bonne.

  • Sessions courtes (recommandé) : 1 tâche = 1 session. Tu fermes en finissant. Tu rouvres pour la suivante.
  • /compact : résume la conversation et libère du contexte sans perdre l'essentiel.
  • /clear : reset complet, destructif. Pour quand la conversation dérive vraiment.

9. Les 5 commandes Git que tu ne dois JAMAIS laisser en autonomie

Même si tu utilises Claude Code en mode auto-accept, ces commandes doivent toujours être manuelles :

  • git push --force (réécrit l'historique distant)
  • git reset --hard (perd les changements locaux)
  • git branch -D (supprime une branche)
  • git rebase (peut casser l'historique)
  • rm -rf (suppression destructive)

Configure ces interdictions dans la section deny de ton settings.json — le hook bloque même si tu acceptes par fatigue.

10. Aller plus loin

Une fois ces fondamentaux maîtrisés, les sujets avancés à creuser :

  • Sub-agents : sous-processus Claude Code à contexte isolé pour tâches longues ou risquées
  • Skills : modules réutilisables qui s'auto-déclenchent selon le contexte
  • MCP servers : brancher Claude Code à des services externes (DB, APIs, GitHub)
  • Hooks : intercepter les événements (PreToolUse, PostToolUse) pour audit ou validation
