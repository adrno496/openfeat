Tutoriel MCP server — Python et TypeScript pour Claude Code

Mis à jour mai 2026 · Lecture 15 min

Le MCP (Model Context Protocol) est le protocole standard pour brancher Claude Code à des services externes : bases de données, APIs tierces, filesystems, services SaaS. Construire ton propre MCP server te donne un super-pouvoir : Claude Code peut alors invoquer tes fonctions custom comme s'il s'agissait d'outils natifs.

Qu'est-ce qu'un MCP server ?

Un MCP server expose 3 types d'éléments :

  • Tools — fonctions invocables (équivalent d'API endpoints)
  • Resources — contenus lisibles (fichiers, données)
  • Prompts — templates de prompts paramétrables

Claude Code joue le rôle de MCP client. Quand tu construis un MCP server custom, tu étends ce que Claude Code peut faire dans ton projet.

Choisir le transport : stdio ou HTTP ?

Deux modes de communication entre Claude Code et ton MCP :

  • stdio : le serveur tourne en local, Claude Code l'invoque via stdin/stdout. Setup trivial, idéal pour usage perso.
  • HTTP : le serveur est distant, communication via HTTPS. Idéal pour serveur partagé (équipe, clients, prod). Demande auth, rate limit, déploiement.

Règle simple : commence en stdio. Passe à HTTP quand l'usage devient partagé.

Tutoriel 1 : MCP server minimal en Python

Installation du SDK :

pip install mcp
# ou avec uv (recommandé)
uv add mcp

Code minimal d'un serveur stdio :

# server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("hello")

@mcp.tool()
def say_hello(name: str = "world") -> str:
    """Dit bonjour à quelqu'un."""
    return f"Hello, {name}"

if __name__ == "__main__":
    mcp.run(transport="stdio")

Configuration côté Claude Code dans .claude/settings.local.json :

{
  "mcpServers": {
    "hello": {
      "command": "python",
      "args": ["/chemin/absolu/vers/server.py"]
    }
  }
}

Lance Claude Code, demande "Utilise le tool say_hello avec name=Axel" — il invoque automatiquement.

Tutoriel 2 : MCP server production en Python avec Pydantic

Pour un MCP qui va en production, il faut validation stricte des inputs, gestion d'erreurs structurée, et logging.

from typing import Literal
import json
from pydantic import BaseModel, Field
from mcp.server.fastmcp import FastMCP
import httpx
import os

mcp = FastMCP("lemonsqueezy")
API_KEY = os.environ["LEMONSQUEEZY_API_KEY"]

class ListSubsInput(BaseModel):
    status: Literal["active", "cancelled", "all"] = "active"
    limit: int = Field(default=10, ge=1, le=50)

@mcp.tool()
async def list_subscriptions(status: str = "active", limit: int = 10) -> str:
    """Liste les abonnements Lemonsqueezy."""
    try:
        params = ListSubsInput(status=status, limit=limit)
    except ValueError as e:
        return json.dumps({"error": "invalid_input", "details": str(e)})

    async with httpx.AsyncClient(timeout=10) as client:
        try:
            res = await client.get(
                "https://api.lemonsqueezy.com/v1/subscriptions",
                headers={"Authorization": f"Bearer {API_KEY}"},
                params={"filter[status]": params.status, "page[size]": params.limit}
            )
            res.raise_for_status()
        except httpx.HTTPStatusError as e:
            return json.dumps({"error": "api_error", "status": e.response.status_code})

    data = res.json()["data"]
    return json.dumps([{"id": s["id"], "email": s["attributes"]["user_email"]} for s in data])

Points clés :

  • Pydantic valide les inputs avant tout appel API
  • Erreurs retournées comme JSON structuré, jamais comme stack trace exposée
  • API key en variable d'environnement, jamais hardcodée
  • Limit max bornée (50) pour éviter d'épuiser le quota API

Tutoriel 3 : MCP server en TypeScript

Installation :

npm install @modelcontextprotocol/sdk zod
npm install -D typescript @types/node

Server stdio minimal :

import { Server } from '@modelcontextprotocol/sdk/server/index.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'
import { z } from 'zod'

const Input = z.object({
  param: z.string().min(1).max(64)
})

const server = new Server(
  { name: 'mon-serveur', version: '1.0.0' },
  { capabilities: { tools: {} } }
)

server.setRequestHandler('tools/list', async () => ({
  tools: [{
    name: 'my_tool',
    description: 'Description claire pour le triggering',
    inputSchema: {
      type: 'object',
      properties: { param: { type: 'string' } },
      required: ['param']
    }
  }]
}))

server.setRequestHandler('tools/call', async (req) => {
  const parsed = Input.parse(req.params.arguments)
  return { content: [{ type: 'text', text: 'OK ' + parsed.param }] }
})

await server.connect(new StdioServerTransport())

Tutoriel 4 : MCP HTTP authentifié avec Express

Pour partager un MCP server avec ton équipe ou tes clients, passage en HTTP avec auth Bearer et rate limiting :

import express from 'express'
import rateLimit from 'express-rate-limit'
import { Server } from '@modelcontextprotocol/sdk/server/index.js'
import { SSEServerTransport } from '@modelcontextprotocol/sdk/server/sse.js'

const TOKENS = new Set([process.env.MCP_TOKEN])
const app = express()

app.use(rateLimit({ windowMs: 60_000, max: 60 }))

app.use((req, res, next) => {
  const token = req.headers.authorization?.replace('Bearer ', '')
  if (!token || !TOKENS.has(token)) {
    return res.status(401).json({ error: 'unauthorized' })
  }
  next()
})

const mcp = new Server({ name: 'shared', version: '1.0.0' }, { capabilities: { tools: {} } })

app.get('/sse', async (_req, res) => {
  const transport = new SSEServerTransport('/messages', res)
  await mcp.connect(transport)
})

app.listen(3000)

Configuration côté Claude Code :

{
  "mcpServers": {
    "shared": {
      "url": "https://mcp.tonsite.com/sse",
      "headers": { "Authorization": "Bearer xxx" }
    }
  }
}

Debugger ton MCP : MCP Inspector

L'outil officiel pour tester un MCP server en standalone :

npx @modelcontextprotocol/inspector python server.py
# ou pour TS
npx @modelcontextprotocol/inspector node dist/server.js

Ouvre une UI web où tu peux invoquer chaque tool avec différents inputs avant de le brancher dans Claude Code. Indispensable pour tester sans polluer ta session.

Bonnes pratiques de sécurité

  • Validation stricte des inputs (Pydantic en Python, Zod en TS)
  • Aucun secret en dur dans le code (toujours os.environ)
  • Erreurs retournées structurées, jamais de stack trace au client
  • Rate limit côté MCP (60 req/min max par défaut)
  • HTTPS obligatoire en prod
  • Auth Bearer avec rotation token tous les 90 jours
  • Audit log de chaque invocation (qui, quand, quoi)

Distribuer ton MCP

3 niveaux de distribution :

  • Privée : ~/.claude/ + dotfiles repo
  • Équipe : repo Git avec .claude/ commité + script de setup
  • Publique : PyPI (uv publish) ou npm (npm publish) + soumission au registry MCP officiel
